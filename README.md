# MSPM0G3507_LibXR_Template

MSPM0G3507 的 LibXR 模板工程 / LibXR template project for the MSPM0G3507

## 1. 板子与平台 / Board and Platform

模板使用 TI MSPM0G3507（Arm Cortex-M0+），SysConfig 工程按 LP-MSPM0G3507 开发板配置，无操作系统，外设由 LibXR 的 `mspm0` 驱动提供（`LIBXR_SYSTEM None`，`LIBXR_DRIVER mspm0`）。初始化代码由 SysConfig 生成，位于 `sysconfig/`。`User/main.c` 调用 `SYSCFG_DL_init()`，把 SysTick 配置为 1 kHz 后调用 `app_main()`，LibXR 应用代码位于 `User/app_main.cpp`。`libxr/` 是 LibXR 子模块，地址为 `https://github.com/xrobot-org/libxr.git`；`mspm0-sdk/` 是 TI 的 MSPM0 SDK 子模块（固定在 `mspm0_sdk_2_09_00_01`）。所用版本均由提交记录固定。`manual.pdf` 是 MSPM0 G 系列技术参考手册（SLAU846C）。

```text
User/app_main.cpp               LibXR 应用代码 app_main()
User/main.c                     SysConfig 初始化、SysTick，调用 app_main()
sysconfig/                      SysConfig 工程 untitled.syscfg 及其生成的初始化代码与链接脚本
Core/                           syscalls 桩函数、栈保留链接脚本
cmake/LibXR.CMake               LibXR 与 MSPM0 SDK 接入
cmake/arm-none-eabi-gcc.cmake   工具链文件
CMakePresets.json               构建预设
scripts/fetch-mspm0-sdk.sh      只获取构建需要的 SDK 文件
ozone.jdebug                    SEGGER Ozone 工程
libxr/ mspm0-sdk/               LibXR 与 MSPM0 SDK 子模块
```

The template uses the TI MSPM0G3507 (Arm Cortex-M0+). The SysConfig project is set up for the LP-MSPM0G3507 board; there is no operating system, and the peripherals are provided by the LibXR `mspm0` driver (`LIBXR_SYSTEM None`, `LIBXR_DRIVER mspm0`). The initialization code is generated by SysConfig and lives in `sysconfig/`. `User/main.c` calls `SYSCFG_DL_init()`, configures SysTick to 1 kHz and calls `app_main()`; the LibXR application code is in `User/app_main.cpp`. `libxr/` is the LibXR submodule at `https://github.com/xrobot-org/libxr.git`, and `mspm0-sdk/` is the TI MSPM0 SDK submodule (pinned at `mspm0_sdk_2_09_00_01`). The commit record pins both versions. `manual.pdf` is the MSPM0 G-Series technical reference manual (SLAU846C).

## 2. 配置一览 / Configurations

| 配置 | 用途 |
| --- | --- |
| `User/app_main.cpp` | UART 回显与 LED 闪烁：创建 `LibXR::MSPM0Timebase`，PB22 上的 LED（`LibXR::MSPM0GPIO`）每 500 ms 翻转一次。UART0（PA0 / PA1，2000000 波特，`LibXR::MSPM0UART`）每 1 s 发送一行 `[mspm0-uart] heartbeat`，并把收到的字节原样回传；接收使用字节中断，发送使用 DMA 通道 0 |

| Configuration | Purpose |
| --- | --- |
| `User/app_main.cpp` | UART echo and LED blink: creates `LibXR::MSPM0Timebase` and toggles the LED on PB22 (`LibXR::MSPM0GPIO`) every 500 ms. UART0 (PA0 / PA1, 2000000 baud, `LibXR::MSPM0UART`) sends the line `[mspm0-uart] heartbeat` every second and echoes the received bytes; reception uses byte interrupts and transmission uses DMA channel 0 |

## 3. 构建 / Build

构建使用 CMake、Ninja 和 `arm-none-eabi-gcc`。`cmake/arm-none-eabi-gcc.cmake` 是工具链文件，编译器前缀由缓存变量 `TOOLCHAIN_PREFIX` 指定（默认 `arm-none-eabi-`，需要在 `PATH` 中）；`CMakePresets.json` 的 `debug` 和 `release` 预设使用该工具链文件，生成器为 Ninja，构建目录为 `build/<预设>/`。镜像 `ghcr.io/xrobot-org/docker-image-mspm0:main` 提供 `arm-none-eabi-gcc` 14.2、CMake 和 Ninja，MSPM0 SDK 由子模块或脚本提供。

```bash
git clone https://github.com/xrobot-org/MSPM0G3507_LibXR_Template.git
cd MSPM0G3507_LibXR_Template
git submodule update --init libxr
sh scripts/fetch-mspm0-sdk.sh
docker run --rm -v "$PWD:/work" -w /work ghcr.io/xrobot-org/docker-image-mspm0:main \
  bash -c 'cmake --preset release && cmake --build --preset release'
```

产物为 `build/release/ti_mspm0_libxr_dev.elf`、`.hex` 和 `.bin`。`git submodule update --init` 会获取完整的 `mspm0-sdk/`，约 2.2 GB；`scripts/fetch-mspm0-sdk.sh` 只获取固定提交中 `source/` 与启动文件，约 300 MB。已有 SDK 目录时，用 `-DMSPM0_SDK_DIR=<SDK 目录>` 指定，例如 `cmake --preset release -DMSPM0_SDK_DIR=/path/to/mspm0_sdk`。

`.github/workflows/build.yml` 在上述镜像中用同一脚本获取 SDK，构建两个预设。其中的 `libxr-master` 作业每天运行一次，把 `libxr/` 更新到 LibXR 的 `master` 后构建，用于提前发现兼容性变化，作业失败不影响工作流结果。

Building uses CMake, Ninja and `arm-none-eabi-gcc`. `cmake/arm-none-eabi-gcc.cmake` is the toolchain file, and the compiler prefix is set by the cache variable `TOOLCHAIN_PREFIX` (default `arm-none-eabi-`, which must be on `PATH`). The `debug` and `release` presets in `CMakePresets.json` use this toolchain file with the Ninja generator and build in `build/<preset>/`. The image `ghcr.io/xrobot-org/docker-image-mspm0:main` provides `arm-none-eabi-gcc` 14.2, CMake and Ninja; the MSPM0 SDK comes from the submodule or from the script.

The output is `build/release/ti_mspm0_libxr_dev.elf`, `.hex` and `.bin`. `git submodule update --init` fetches the complete `mspm0-sdk/`, about 2.2 GB, while `scripts/fetch-mspm0-sdk.sh` fetches only `source/` and the startup file of the pinned commit, about 300 MB. An existing SDK directory is selected with `-DMSPM0_SDK_DIR=<SDK directory>`, for example `cmake --preset release -DMSPM0_SDK_DIR=/path/to/mspm0_sdk`.

`.github/workflows/build.yml` fetches the SDK with the same script in the image above and builds both presets. Its `libxr-master` job runs daily, updates `libxr/` to the LibXR `master` branch and builds, which reveals compatibility changes early; a failure of that job does not fail the workflow.

## 4. 烧录与运行 / Flash and Run

`ozone.jdebug` 是 SEGGER Ozone 工程，设备为 MSPM0G3507，调试接口为 SWD（4 MHz），加载 `build/debug/ti_mspm0_libxr_dev.elf`。先构建 `debug` 预设，再在 Ozone 中打开该工程即可下载并调试。

运行后 PB22 上的 LED 每 500 ms 翻转一次，UART0 每秒输出 `[mspm0-uart] heartbeat`，并回传收到的字节。

`ozone.jdebug` is a SEGGER Ozone project for the MSPM0G3507 over SWD (4 MHz) that loads `build/debug/ti_mspm0_libxr_dev.elf`. After building the `debug` preset, opening the project in Ozone downloads and debugs the firmware.

At run time the LED on PB22 toggles every 500 ms, and UART0 prints `[mspm0-uart] heartbeat` every second and echoes the bytes it receives.
